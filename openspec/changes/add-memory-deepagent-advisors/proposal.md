## Why

The memory hint, rerank, and integrity services currently have deterministic fallback logic, but the product behavior should be agentic: hints should be generated by a real LLM/DeepAgent path, reranking should make pedagogical judgments, and integrity should use semantic advice for ambiguous duplicate or conflict decisions. At the same time, shared enum vocabulary should be centralized so schemas, services, MCP tools, and agents all use one stable contract.

## What Changes

- Move shared memory integrity, hint, teaching-action, and rerank-purpose enums from `entities.py` into `schema/enums.py`.
- Add a real DeepAgent/LLM-backed hint advisor that generates structured low-spoiler hints from task context, submitted code, retrieved memory, and requested hint level.
- Add a real DeepAgent/LLM-backed memory rerank advisor that selects candidate memories and returns purpose-specific teaching guidance.
- Add a real DeepAgent/LLM-backed memory integrity advisor for ambiguous duplicate/conflict decisions over a bounded candidate set.
- Make the LLM advisor path the normal production path when credentials/configuration are available, while keeping deterministic behavior as validation and fallback.
- Add LangSmith-observable smoke coverage for the real advisor path.
- Preserve service ownership of all database writes; no advisor or agent can directly mutate learner memory.

## Capabilities

### New Capabilities

- `memory-advisor-agents`: Real DeepAgent/LLM advisors for hint generation, memory reranking, and memory integrity decisions.
- `schema-enum-contracts`: Centralized enum ownership for schema vocabulary shared by entities, services, tools, and agents.

### Modified Capabilities

- `memory-aware-hints`: Hints are generated by the LLM hint advisor in the normal path, with deterministic fallback only when the advisor is unavailable or invalid.
- `memory-rerank-policy`: Reranking uses the LLM advisor in the normal path, validates selected memory IDs, and falls back to deterministic ranking on failure.
- `memory-integrity-lifecycle`: Ambiguous integrity decisions may use the LLM advisor, but persistence remains service-owned and validated.

## Impact

- Affects `backend/app/schema/enums.py` and enum imports from schema, services, tests, MCP tools, and agents.
- Adds new agent/advisor modules near existing validator/content-generator agent patterns.
- Updates `memory_hint`, `memory_rerank_policy`, and `memory_integrity` services to invoke advisors by default when enabled.
- Adds tests for enum imports, advisor validation, fallback behavior, and live smoke coverage.
- Adds documentation for advisor configuration, LangSmith observation, and service-owned DB write guardrails.
